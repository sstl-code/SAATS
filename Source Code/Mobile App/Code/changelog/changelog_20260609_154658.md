# Changelog: Asset Tagging Implementation Fixes (2026-06-09 15:46:58)

## Overview
This changelog details the issues identified and resolved during the debugging of the Asset Tagging submission flow in the `Deliverain` branch. The fixes address issues where the tagging modal dialog did not close, the asset image failed to upload to the server, and server-side responses/database constraints caused errors.

---

## 1. Mobile Client Code Changes

### File: `lib/utils/tag_asset/tag_asset.dart`
- **Issue**: The tagging modal's **OK** and **Cancel** buttons used the page-level `context` instead of the dialog's custom `BuildContext` when calling `Navigator.pop(context)`. This left the dialog modal open on the screen even after a successful action.
- **Resolution**: Wrapped the footer `Row` in a `Builder` widget to expose the dialog-specific `BuildContext` (`dialogContext`). Updated both button actions to call `Navigator.pop(dialogContext)`.

### File: `lib/api_client/api_client.dart`
- **Issue**: The file attachment routine (`addFilesToRequest`) used an asynchronous `forEach` loop to read file bytes:
  ```dart
  myMap.forEach((key, value) async { ... })
  ```
  In Dart, `forEach` does not await asynchronous callbacks. The function returned and the HTTP request was sent before the file bytes were actually read and added to the request, resulting in empty or missing image uploads.
- **Resolution**: Replaced the `forEach` iteration with a standard `for (var entry in myMap.entries)` loop, ensuring that the asynchronous `await file.readAsBytes()` is correctly awaited before executing the request.

### File: `lib/screens/asset_details/data/asset_repository.dart`
- **Issue**: The `imageUpload` repository method defaulted to returning `ImageResponse(status: 401)` on any server-side validation error (e.g. 404 validation errors), masking the actual error messages sent back by the PHP backend.
- **Resolution**: Updated `imageUpload` to check if the error response contains a JSON Map body. If present, it parses and returns the actual `ImageResponse` with the server's custom message (e.g., `"please give a unique tag number"`), which is then correctly shown to the user in a toast notification.

## 2. Database (PostgreSQL) Changes

### Table: `ats.t_asset_edit_attribute`
- **Issue**: Submitting a unique tag number triggered the database error:
  `duplicate key value violates unique constraint - t_asset_edit_attribute_pkey`
  This occurred because the primary key sequence (`t_asset_attribute_at_asset_edit_attribute_id_seq`) fell out of sync with the actual data in the table, likely due to a manual import or copy process that inserted explicit primary keys without updating the sequence generator.
- **Resolution**: Reset the sequence value to start after the highest existing ID in the table using the following SQL query:
  ```sql
  SELECT setval(
      'ats.t_asset_attribute_at_asset_edit_attribute_id_seq', 
      COALESCE((SELECT MAX(id) FROM ats.t_asset_edit_attribute), 0) + 1, 
      false
  );
  ```
